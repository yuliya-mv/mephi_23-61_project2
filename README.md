# Модуль баз данных

Проект представляет собой модуль для управления таблицами. Может создавать, проверять и удалять таблицы, определять их структуру с типами данных и сохранять метаданные в JSON-файл для персистентности.

**Возможности**

* Создание таблиц с заданными столбцами и типами данных.
* Автоматическая генерация уникального ID для каждой новой записи.
* Просмотр списка таблиц и информации об их структуре.
* Добавление, чтение, изменение и удаление записей (CRUD).
* Проверка типов данных и корректности команд.
* Сохранение метаданных и записей в JSON-файлах.
* Подтверждение удаления таблиц и записей.
* Кэширование результатов запросов select.
* Измерение времени выполнения функций с помощью декораторов.

## Библиотеки и зависимости

* Внешние: ruff (для разработки), prettytable (для форматированного вывода).
* Стандартные: json для работы с файлами, shlex для безопасного парсинга команд (Важно: Модуль shlex предназначен только для оболочек Unix), time для измерения времени выполнения, os — работа с файлами и каталогами.


## Установка

Проект требует установку uv или poetry

| Инструмент | Установка | Запуск |
|---|---|---|
| **UV** | `uv sync` | `uv run database` |
| **Poetry** | `poetry install` | `poetry run database` |


## Типы данных

| Тип | Пример |
|---|---|
| `int` | `28` |
| `str` | `"Sergei"` |
| `bool` | `true`, `false` |

Логические значения можно вводить как True, False, TRUE и FALSE.

При создании таблицы столбец ID:int добавляется автоматически и располагается первым, однако если id:int указано вручную, то дублирования столбца ID не произойдёт. Значение ID назначается при добавлении записи. Вручную добавлять или изменять ID нельзя.

Строковые значения указываются в двойных кавычках. Числа и логические значения вводятся без кавычек.

```

<command> list_tables - показать список всех таблиц
<command> drop_table <имя_таблицы> - удалить таблицу
<command> exit - выход из программы
<command> help - справочная информация

```

## Декораторы и замыкания

В проекте используются декораторы и замыкания для вынесения повторяющейся логики в отдельные функции.

* handle_db_errors — обрабатывает предусмотренные ошибки базы данных.
* confirm_action — запрашивает подтверждение перед удалением.
* log_time — измеряет и выводит время выполнения функции.
* create_cacher — создаёт замыкание для кэширования результатов запросов.

После успешного изменения данных кэш очищается, чтобы последующие запросы возвращали актуальную информацию.
